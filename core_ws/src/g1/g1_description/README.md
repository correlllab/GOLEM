# g1_description

Robot description for the Unitree G1 (29 DoF) with Dex3-1 hands: the URDFs and
meshes, the joint table and the DDS motor layout. The other G1 packages take
their URDFs, joint names, DDS slots and limits from here.

## What it installs

The URDFs and meshes come from the `leprechaun_g1` submodule in the repo's
`third_party/`, which vendors them unchanged from Unitree's `unitree_ros`.
`setup.py` reads them through the package's `leprechaun_g1` symlink (to
`../../../../third_party/leprechaun_g1`) and stops if the submodule is not
checked out. The symlink keeps the data files inside the package, which
colcon's `--symlink-install` needs. In
Docker the `ros` service mounts it at `/home/code/third_party/leprechaun_g1`.

Under `share/g1_description/assets/`:

- `g1_29dof_with_hand_rev_1_0.urdf`: the body with both Dex3-1 hands (our
    robot).
- `g1_29dof_rev_1_0.urdf`: the body only, with rubber hands.
- `*_ros.urdf`: a copy of each with `package://g1_description/assets/meshes/`
    mesh URIs, for `robot_state_publisher` and RViz. `setup.py` writes them into
    `_install_staging/` at build time. The upstream files keep their relative
    `meshes/...` paths, which resolve against `assets/` (Pinocchio loads these).
- `meshes/`: the 51 STL meshes.
- `LICENSE.unitree_ros`: Unitree's BSD 3-Clause license for the models.

It also installs `launch/display.launch.py` and `rviz/g1.rviz`.

## Python modules

- `joints.py`: `BODY`, the 29 body joints in `rt/lowcmd` / `rt/lowstate` order,
    and `LEFT_HAND`, `RIGHT_HAND`, 7 joints each in `rt/dex3/<side>/cmd` order.
    Each `Joint` holds the name, the DDS slot and the URDF limits (position,
    velocity, effort).
    - The limits are Unitree's model values, not measurements of our unit. The
      URDF gives the ankles and waist roll/pitch 35 Nm where the MJCF says
      50 Nm.
- `layout.py`: which DDS slot is which.
    - Legs 0-11, waist 12-14, left arm 15-21, right arm 22-28; `LowCmd_` has 35
      slots.
    - `rt/arm_sdk` drives slots 12-28 (`ARM_SDK_SLOTS`). The `q` of slot 29
      (`ARM_SDK_WEIGHT_SLOT`) hands control over: 1.0 for our commands, 0.0 for
      Unitree's controller.
    - `mode_pr` must be `MODE_PR` (0), so the ankle slots drive the pitch and
      roll joints the table names. `mode_machine` must echo the value read from
      `rt/lowstate` (our unit reports 5).
    - Lookups: `BODY_JOINT_NAMES`, `SLOT_BY_NAME`, `HAND_JOINT_NAMES`.
- `paths.py`: `urdf_path(variant='with_hand', ros=False)` gives an installed
    URDF; `variant='body'` selects the body-only model and `ros=True` the
    `package://` copy. `assets_dir()` gives the installed `assets/`.

`joints.py` and `layout.py` import straight from the source tree (the other
packages' tests put `../g1_description` on `PYTHONPATH`). `urdf_path()` and
`assets_dir()` need the package built and sourced. `import g1_description`
re-exports all of them.

## Regenerating joints.py

`joints.py` is generated by `tools/generate_joints.py`; never edit it by hand.
Change the generator, then rerun it (it needs the `leprechaun_g1` submodule):

```bash
python3 tools/generate_joints.py           # rewrite g1_description/joints.py
python3 tools/generate_joints.py --check   # exit 1 if joints.py is stale
```

The limits come from the with-hand URDF. The body order comes from Unitree's SDK
(`G1JointIndex`) and is checked against the body-only MJCF's actuators; the hand
order is Unitree's `HandCmd_` order. The tests fail if `joints.py` no longer
matches the URDF.

## Show the robot in RViz

```bash
ros2 launch g1_description display.launch.py                # body + Dex3-1 hands, joint sliders
ros2 launch g1_description display.launch.py hands:=false   # body only
ros2 launch g1_description display.launch.py gui:=false rviz:=false   # headless TF, joints at 0
```

It runs `robot_state_publisher` on a `*_ros.urdf`, the joint sliders
(`joint_state_publisher_gui`, or `joint_state_publisher` with `gui:=false`) and
RViz. It never commands the robot; it publishes `/joint_states`,
`/robot_description` and TF.

## Tests

```bash
PYTHONPATH=. python3 -m pytest test
```

The tests check the slot layout, the joint tables and their limits, and that
`joints.py` matches the URDF (skipped when `leprechaun_g1` is not checked out).
They need neither ROS nor DDS.
