H1-2 Real
Deployment Guide

Run only what you need: camera localization without joint commands, upper-body control with the robot supported by the crane, or the complete standing and peg task in the final section.

ROBOT means the onboard computer; LOCAL means the companion workstation. These are native ROS 2 commands, not simulation launchers. Hardware operation still requires the team's approved calibration, configurations and physical stop procedure.

02 / Prepare the Terminals

  1. Choose A, B or C before launching anything. Camera-only does not require starting a controller.
  2. For any actuation, assign an operator and physical E-stop operator; verify crane/support, exclusion area, empty hands, feet, complete initialization sweep and stop/power procedure.
  3. Verify device identities, permissions, synchronized clocks and camera delivery between hosts. For A2/B/C, also verify the required Unitree DDS routing and measured state/TF.
  4. For B/C, approve exactly one final rt/lowcmd writer, the safety relay, and the matching real upper/safety YAMLs, mappings, gains, limits and stale-data behavior. Upper and lower controllers publish only split inputs. Stage A starts no command writer.
  5. Approve the lower policy and physical marker/gripper profile only when proceeding to Stage C. Do not use simulation compensation or simulation safety profiles on hardware.

Use one clean bash terminal per long-running component. Set GOLEM_ROOT to this host's absolute checkout path, then prepare every terminal. No hostname or path is shared implicitly between ROBOT and LOCAL.

Require every setup line to succeed. Keep ROS/vision on ROS Python (NumPy 1); use the explicit Controller Python (NumPy 2, Pinocchio/Crocoddyl/OMPL) prefixes only for arms and joint-state publishing. Do not globally activate the controller venv for the camera/localizer. Camera-frame localization needs no Controller Python, standing policy or ML weights.

Network: both hosts use wall time and ROS_DOMAIN_ID=0, with synchronized clocks and approved ROS DDS discovery/routing. Unitree SDK participants also need the correct NIC: upper/safety YAMLs carry network.interface; the environment domain does not select it. The sample real upper profile hardcodes eno1, which may be wrong on LOCAL.

Every APPROVED_* value must be explicitly supplied. File paths are absolute, existing files on the host that consumes them. Re-check the model, NIC, split input/output topics, hardware gains/limits and watchdogs; do not treat a shipped YAML as hardware approval.

Build once, before hardware power or connection

Provide ROS 2 Humble, Python 3.10 and environments/ros/apt-packages.txt prerequisites, committed submodule pins and Git-LFS assets. Check host architecture; do not copy venvs/install trees from another machine. Build while disconnected from hardware.

Install Controller Python only on hosts running the upper controller or joint-state subscriber. An existing approved ROS install is sufficient for camera-only operation; the build above is the complete native overlay, not a minimal camera installer. The experiment build does not install hardware drivers. Provide approved cl_realsense/realsense2_camera, librealsense, image transport, Magpie/Dynamixel, udev and E-stop serial dependencies separately on their device hosts.

Simulation-only wrappers run_simulation.sh, run_controller.sh, run_ros.sh and run_rviz.sh reject domain 0. Do not bypass those guards or run a simulator on the hardware bus.

03 / Stage A: Camera Localization Only

This stage starts no safety relay, arm controller, lower policy, gripper driver or skill server. Keep any other robot software under the approved hardware procedure; these commands add observation only.

A1 / Camera-frame localization, no robot-state dependency

Start the camera on its actual USB host, normally ROBOT. Verify the serial in the launch file; its current setting is _250122072330 at 1280 x 720, 15 FPS.

Set HEAD_OPTICAL_FRAME to the exact observed header.frame_id (normally head_color_optical_frame). Then start one localizer:

The same-frame TF lookup is identity, so A1 needs only images and matching CameraInfo. Check diagnostics and annotated images using Section 05. Camera-frame output is for perception inspection, not a pelvis-frame arm goal. Do not start skills against it.

A2 / Optional pelvis-frame localization, still no joint commands

For robot-relative localization or RViz, add one read-only state/TF pair on LOCAL (or move this entire pair onboard). It subscribes to actual rt/lowstate; it does not construct an upper controller or command publisher.

This state launch uses the default reader configuration with automatic NIC selection; it has no state-config argument. Approve DDS routing first. If an explicit state-reader NIC is required, use the alternative below instead of this launch.

Explicit NIC for the read-only state reader

This replaces the A2 h12_state.launch.py command above. Start these two independent processes on the chosen state host. The first uses a reviewed controller-format YAML solely to select its input DDS domain/NIC/topic; it publishes joint states, not commands. The second uses Humble's supported URDF-file argument.

Stop only A1's localizer with Ctrl+C, leaving the camera running. Relaunch it for pelvis output; do not run two localizers publishing the same topics:

Wait for the camera launch's delayed mounting TF (10 seconds), matching image/CameraInfo stamps and fresh target_frame=pelvis diagnostics. The chain is measured joints → pelvis/torso/head mount → calibrated camera mount → optical frame. Do not replace missing measured TF with invented static joint poses.

Raw transport is the baseline. If the camera host actually publishes /realsense/head/color/image_raw/compressed and its plugin is installed, relaunch the same localizer with image_transport:=compressed for the workstation link. No simulator, /clock, LiDAR/SLAM, AI model server or ground-truth publisher is required.

Marker print layout and optional RViz

Use DICT_4X4_50, ID 7 top-left and ID 8 top-right. Each 30 mm black code sits on a 40 mm paper square with a full 5 mm white border. Mount paper flush to the top and adjacent board side edges without changing orientation: centres (-140, 105) and (140, 105) mm in board-local X/Y. PnP uses the black-code edge, not paper size. Use an ArUco print generator, measure printed scale and check the shared layout; catalog suffixes 0..3 mean clearance rows, not peg sizes.

The supplied RViz configuration expects pelvis-frame output and A2 state/TF. For A1, inspect the annotated image or explicitly choose the observed optical frame in RViz; the pelvis configuration is not a camera-only prerequisite. Check measured grasp-frame TF, RGB and diagnostics rather than a stale pose arrow.

04 / Stage B: Crane-Supported Upper Body Only

This recipe is independent of Stage A: named/manual arm goals need direct measured Unitree state, not a camera, ArUco, skills or a lower policy. Add A2 only if you want pelvis-frame localization and RViz. Keep the physical crane/support engaged for this entire stage.

Actuation starts at launch. The upper server enables arms and torso, starts its publisher, then moves through init_1 → init_2 → init_3 → home and torso initialization. init=False is not a read-only mode. A false lower-body start gate does not inhibit these upper motions.

B1 / Mechanical and command-path gate

Fully support the robot's weight, control any free leg motion, clear the complete arm/torso sweep, and complete the approved handover from any vendor controller. Assign exactly one final writer. No lower-body process may be running. Do not call /lowerbody/confirm_engage, any elastic-band service, or a simulation hoist option.

Start a fresh split safety relay. With no lower source its leg command slots start inactive; this is not a leg posture hold, vendor-controller pass-through, or standing mode. Do not reuse a relay that previously cached standing commands: stopping a lower publisher does not erase those cached commands.

B2 / Safety on ROBOT, upper controller LOCAL

In the main recipe, ROBOT owns the physical E-stop and final safety writer; LOCAL runs the arm solver. Verify the E-stop device/receiver and reviewed safety YAML before launching the writer:

Check actual E-stop status at the receiver, fresh robot state and the relay before continuing. Launch delays and a true safety heartbeat are not proof of a functioning stop chain; see Section 05.

LOCAL must have direct, approved Unitree DDS connectivity; forwarding ROS camera topics alone is insufficient. Wait for measured initialization and the server-ready log. A startup convergence warning is not measured home.

Alternative: keep the upper controller on ROBOT

This replaces both B2 commands, not adds to them. ROBOT now needs Controller Python and the approved model/config. Complete the entire physical gate before launching: the arm server starts after a timer, without an interactive approval prompt.

B3 / Empty-hand upper-body check, crane remains supporting

Verify measured arms are home. Start with Frame mode and an approved bounded empty-hand target. Counter is optional and may move the opposite arm; clear its whole workspace too. A crane-supported result is not evidence of free-standing balance.

Return to Frame with ros_cli param set /frame_task_server control_mode frame. The setting itself does not move the robot; changes while busy are rejected. Do not restart the controller to switch modes.

Manual plan-only and replay, without skills or standing

Supply an inspected hardware FrameTask YAML with plan: true, matching nonempty frame/target lists and a checked path. The plan-only call adds no motor motion, but the already-running server continues holding its prior command.

Replay validates the measured start and saved path, uses stored timing and does not replan. The duration is a wall-clock budget, not a requested motion time. Ordinary /frame_task with plan: true instead plans and executes in one call.

To repeat, return using /named_config with config_name: 'approach_start' and plan: true, then replay while still supported. Cache contents are RAM-only. Named planning and ordinary planned motions do not overwrite the explicit saved approach.

The upper-body-only session ends here. Keep lower body and marker skills off and use Section 05 to stop. If you later want a crane-supported peg trial, use the supported variant in the final section; standing is not a software prerequisite for marker skills.

For camera failures, check serial/USB, image transport, print layout, CameraInfo and clock synchronization before TF or calibration changes. A2 waits up to the configured observation age for exact-time TF; do not substitute a latest/stale transform or loosen bounds to force acceptance.

Current safety limits to account for: the raw E-stop monitor checks triggered/unplugged status when a sample exists, but does not fail closed on a never-received or stale sample. Its heartbeat alone cannot certify the physical stop chain or relay worker. Require an independently tested physical stop path and approved monitoring. The shipped relax_safety_split.yaml also disables the upper-command staleness watchdog; do not silently use that default for a remote arm process.

Normal exit from A: stop the localizer, optional state/TF and camera; no command path was started. Normal exit from B/C: finish or cancel the task, secure the payload, restore physical robot support, then use the team's approved control/power shutdown order. Losing LOCAL is not a normal stop procedure. Safety may latch when an upper publisher disappears.

For danger, use the tested physical E-stop/emergency procedure. Ctrl+C, ROS cancellation and a true heartbeat are not independent emergency stops. The last command may remain held; no automatic retreat, release or support recovery is promised. If returning from C to upper-only, first secure and shut down safely, then start B with a fresh relay; merely stopping the lower node leaves cached leg commands.

06 / Stage C: Standing and Peg-in-Hole Workflow

This is the final, optional stage. Retain the qualified Stage B safety/upper processes; add missing A2 camera, measured state/TF and the single pelvis-frame localizer. Do not relaunch components that are already running. There is no need to start SLAM, Nav2 or the heavyweight model-server bringup for this marker task.

Choose the support condition before starting. For full standing, follow C1 through C5. For a crane-supported grasp/extraction trial, skip C1 entirely, keep all lower nodes off, and use C2 through C5 with qualified Stage B support. Keep the rig/workcell stable during motion and record the result as supported manipulation, not a standing evaluation. Never change support condition during a task.

Use the real 320 x 250 mm board and the approved seated source. Review the complete named prep sweep and approach against the physical table: robot self-collision planning does not model arbitrary table/board obstacles. A localization result alone is not a contact-geometry calibration.

C1 / Full-standing Variant Only: Add Lower Body on ROBOT

Complete the approved real start-pose check before setting the gate true. Select the explicitly approved manipulation-standing policy/configuration: almi_manip_stand and fame_finetune are distinct from legacy almi and fame. No policy is implicitly hardware-qualified by this guide.

Require engage_wait_for_confirm: true and disable_elastic_band: false in that reviewed configuration. The latter avoids the simulation-only /elastic_band/toggle path; it does not lower the physical crane. Check IMU calibration, startup bounds and measured leg settling. A pre-pose timeout, guard rejection or frozen output is not readiness; do not confirm or bypass the guard.

While still supported, recheck measured arm home from B3, feet and all clearances, fresh state and the tested E-stop chain. Only when the physical operator is ready, explicitly engage:

Do not pre-call or chain this service to launch. Coordinate crane/support handover physically using the approved procedure and wait for measured stable standing before task motions. A service success does not prove balance. If state, policy output, safety or posture is unhealthy, stop under the physical procedure.

C2 / Add physical grippers and calibrated marker skills

Verify both gripper USB identities and an empty, clear finger workspace. The existing launch has fixed device paths, not port arguments; it initializes hardware speed/torque. Skip it if an approved owner already drives those devices.

No qualified physical marker/gripper profile is supplied by this procedure. Do not substitute marker_profile_sim_extraction.json, a nominal simulation profile, simulation safety YAMLs or unreviewed camera/contact offsets. The existing head-mount calibration reports roughly ±13 mm / 1.5° accuracy; this is not insertion-level qualification.

Choose Frame or Counter on the same idle server using B3. Keep the opposite hand empty and its sweep clear. Do not change gains/configuration, switch modes mid-task or restart controllers between trials.

C3 / Grasp or Extract, One Freshly Seated Source

Verify the source peg is seated, the real profile matches it, and the complete path is clear. Default approach_mode=plan performs ordinary named preparation, acquires a fresh ArUco board snapshot, plans one approach, executes it, then contacts and grasps. The named prep and tool geometry must be approved for this fixture; self-collision planning does not model arbitrary table/board obstacles.

Choose one task from a freshly seated source. The recipe is identical in Frame or Counter mode. Pick/place includes its own grasp; do not call it after grasp-only.

Grasp only

Extract and hold

Marker pick/place does not insert or release. Its top_down path requires 90 degrees internally; min_downward_pitch_deg exists only on SkillGrasp. Keep visual_servo: false. Verify contact and actual extraction/retention rather than inferring them from action success.

The bounded trajectory uses the accepted start snapshot, so markers need not remain visible behind the hand throughout motion. Joint, limit, reached-target and cancellation guards remain active. On failure, stop issuing goals, keep the reported cause and inspect the held posture/payload. Cancellation is not an E-stop or automatic withdrawal.

C4 / Return and Reuse

Keep the chosen support condition and existing processes unchanged. In the standing variant, also keep the lower controller running; in the supported variant, keep it off. For grasp-only, verify the peg remains seated and supported, then open with the approved physical aperture before returning:

After extraction, secure and physically restore the peg to its original seated source under the approved fixture procedure before repeating. Never open a loaded hand blindly or move the fixture around an actively moving robot. Return with empty hands and a checked path:

Wait for success. This is the home for the recorded approach, not ordinary home, which may differ from its prepared start. It does not reset the lower body or restore objects.

Optionally switch control_mode while idle, recheck the restored source/workcell, then send the same task goal. Reuse checks a fresh observation against existing workcell bounds but keeps the original task target snapshot and saved path. A wrong measured start is rejected, not automatically returned.

For a changed scene/task, set ros_cli param set /h12_skills approach_mode plan and plan again. A new plan replaces the old cache. The path and snapshot are RAM-only and do not survive controller/skills restarts. Each explicit goal assumes the operator has restored and checked its input scenario.

C5 / Record the Outcome and Stop Safely

Use Section 05 for shutdown. Record measured standing, actual peg displacement/retention, contacts, task result/failure text, software/configuration/profile revisions, checkpoint identity and support condition. The current skill has no autonomous insertion, release or grip-retention verification; a successful action is not a completed peg-in-hole assembly.

Component references and failed acquisition

If board acquisition fails, read /perception/pegboard/diagnostics and check print layout, CameraInfo, timestamp synchronization and TF at the image stamp. Do not loosen bounds or tune gains to bypass a rejected goal.
