Native Linux / MuJoCo / ROS 2 Humble

H1-2 Simulation
Task Guide

Launch the pegboard scene, start one controller, engage standing, then grasp or extract with Frame or Counter. Return to the recorded approach start to reuse the same plan without restarting standing.

Run commands from the GOLEM root in clean bash or zsh terminals, outside Conda. Set ROS_DOMAIN_ID=1 in every terminal. The simulation helpers reject domain 0; hardware uses the separate real deployment guide.

01 / Prepare Once

Use Linux with ROS 2 Humble, system Python 3.10, initialized submodules and Git-LFS assets. System prerequisites are listed in environments/ros/apt-packages.txt. A prepared checkout can go directly to step 02.

First-time dependency setup and build

Run in this order. The wrappers keep ROS/vision on NumPy 1 and the controller/simulator in their separate NumPy 2 environments; do not activate or combine their Python paths manually. Setup does not install system packages or need sudo.

Require each command to succeed. Repeat the relevant build after source/interface changes. Everyday launch does not install or compile dependencies. This geometric marker workflow needs no cloud API key or AI model weights.

02 / Launch Simulation

In Terminal A, start the simulator once and leave it running.

The scene contains a table and a 320 x 250 mm pegboard on the robot's left, with cylinder_1 seated in source hole cylinder_1. The lower-body option selects the initial pose and pelvis fit, not a running policy. Inspect the actual pose, feet and clearances before starting control; leave the startup tether alone until engagement.

--task-tools enables the existing object-only reset for repeated simulation trials. It also advertises evaluation ground truth; neither localization nor the controller uses that output. This option is not used on the real robot.

Scene composition, markers and camera

Board entry height is 25 mm above its origin. Catalog suffixes 0..3 are clearance rows, not different peg sizes. Changing --peg or --source-hole requires a matching skill profile; simulator flags do not update it.

Use DICT_4X4_50, ID 7 top-left and ID 8 top-right: 30 mm black codes on 40 mm paper squares, mounted flush to the top and adjacent side edges, with unchanged orientation and full 5 mm white borders. Board-local centres are (-140, 105) and (140, 105) mm. PnP uses the 30 mm black edge. Use an ArUco print generator with those IDs and check printed scale. The simulator marker generator and shared layout define the matching scene geometry.

PegInHole selects full-resolution head RGB, matching CameraInfo and compressed transport through the controller helper; no inline camera flags are needed. Localization uses the real head-camera geometry and timestamped TF, not object ground truth or an overhead camera. Either marker can provide an accepted pose.

For a machine without a display, append --headless to the same simulator command. Optional --timing reports real-time factor. These change the one launch, not add another simulator.

03 / Launch Controller

Verify the held start posture and empty, clear arm workspace. Then start one controller in Terminal B. start_position_verified:=true is your physical-pose assertion; startup itself moves joints.

The helper starts state/TF, safety, ALMI lower-body control, marker localization and skills, and one Counter-capable arm server in frame mode. It selects compressed image transport and the simulator distal-grasp profile internally. Do not start a second bringup or a separate Frame controller.

Wait for init_1, init_2, init_3, home, torso initialization and Frame Task Server initialized. Initialization and named postures use plain posture control, not counter-motion.

04 / Engage Lower Body

Wait for controller initialization, settled legs and the confirmation prompt. With the startup tether still enabled and the arm sweep clear, explicitly finish moving both arms home:

Wait for success and check that the measured arms are home, not merely commanded home. Check the actual leg posture and fresh safety/state data; an initialization warning or settle timeout is not measured convergence. Only then engage standing:

This activates the selected policy and automatically releases the simulator tether through the existing engagement sequence. Do not pre-call the service, chain it to launch, or manually toggle the tether. Wait for stable standing before any arm goal. If standing is unstable, stop the task and keep the actual failure message and logs rather than continuing into a grasp.

Optional RViz inspection

Use pelvis as the fixed frame. Inspect the measured grasp frames, head image, board axes and diagnostics. A persistent pose arrow is not a fresh observation; raw wrist poses are not GRASPGENX tool poses.

05 / Choose Frame or Counter

One controller supports two execution modes. Frame follows the ordinary arm task; Counter also allows the opposite arm to counter-move. Keep that free hand empty and its whole workspace clear. Choose a mode only between completely finished tasks:

For Frame, use ./scripts/run_ros.sh param set /frame_task_server control_mode frame. A parameter update does not move the robot. Busy changes are rejected. Do not restart standing or the controller to switch modes, and do not change parameters mid-goal.

06 / Grasp or Extract

Start with the expected peg seated at its source, a clear workcell and fresh valid board localization. On a new task, the default approach_mode=plan automatically performs ordinary named preparation, takes a fresh ArUco board snapshot, plans the approach once, executes it, then performs contact and grasp. No manual three-pose staging is required.

Choose one alternative below. Both use the same selected Frame/Counter mode and left-arm vertical approach. Do not send pick/place after grasp-only: it includes its own grasp and expects a freshly seated source.

A / Grasp only

B / Extract and hold

Marker pick/place grasps, extracts along the board normal, carries and holds at pre-insertion. It does not insert or release. SkillPickPlace has no min_downward_pitch_deg field; its top-down path enforces 90 degrees internally. Keep visual_servo: false.

The task acquires its board snapshot at the start; a bounded executing trajectory does not require markers to stay visible behind the gripper. Joint, limit, cancellation and reached-target guards remain active. Check actual peg contact, motion and retention, not just action success. On failure, read the reported cause, wait for the goal to stop and inspect the current pose before another command; there is no automatic withdrawal.

07 / Return and Reuse

Keep simulation, controller and standing running. After grasp-only, the peg remains seated: open the hand before returning. After extraction, release the peg only where it can fall safely in the simulation, then clear the empty hand. Do not reset objects while the hand holds or contacts the peg.

With the hand empty and return clearance checked, return both upper arms to the recorded approach start, the home for this particular approach:

Wait for success. Ordinary home is a different posture and is not necessarily the path's start. Neither posture command resets the lower body or restores objects.

After an extraction, restore the source peg using the object-only reset. Call it only after the task has stopped and the open hand has returned clear of the source. It preserves robot state, the standing process, simulation time and the saved approach.

Optionally select the other control_mode while idle, recheck the restored source and workcell, then send the same task goal. Reuse checks a fresh workcell observation against existing bounds, but keeps the original target snapshot and saved approach without replanning. A wrong start is rejected, not automatically corrected.

For a new scene/task, set ./scripts/run_ros.sh param set /h12_skills approach_mode plan before the goal; its new plan replaces the cache. Saved paths and task snapshots live only in process memory: controller/skills restarts require planning again. You are responsible for restoring the input scenario before every explicit goal.

08 / Details and Shutdown

Manual arm task: plan once, return and replay

For an empty-hand, clearance-checked manual task, ordinary /frame_task still plans/executes one goal. The separate /plan_frame_task endpoint saves one explicit approach without movement:

Replay freshly validates the measured start and stored path and uses its saved timing under the current mode. For another replay, return through approach_start first. An optional frame-name assertion may be supplied; a new target is not needed. Named planning and ordinary planned carry goals do not overwrite this explicit cache. A new explicit plan does. Duration is an execution budget, not a requested movement time; the adapter paces execution on wall time.

Planning checks modeled joints and self-collision, not arbitrary table/board obstacles. Inspect the entire path and free-arm clearance.

Alternative policy or supported bringup

For an owner-approved FAME task, replace the simulator selection with --lowerbody fame_finetune and add lowerbody:=fame_finetune to the controller launch. Select the same policy independently in both terminals, then follow the settle-and-engage step.

--manipulation-hoist adds rotational pelvis support for a deliberately supported experiment. It is not the main standing workflow and must be recorded as a different support condition. Leaving a policy unengaged under support is not standing. Do not mix supported results with engaged-standing results.

Localization, calibration and actionable failures

Read /perception/pegboard/diagnostics when acquisition fails. Check image/CameraInfo delivery, original-image timestamp TF, marker layout and observation freshness. Do not relax bounds or gains to make a rejected goal run. If a controller reports waypoint not reached, keep its feedback; if a skill reports cancellation, keep the guard reason after the colon.

The helper's distal simulation profile matches this cylinder/source and simulated gripper mapping. It is not a physical hardware calibration. Use an approved real profile on hardware, never this file.

For normal shutdown, finish/stop the active task and secure any held object, stop controller bringup with Ctrl+C and wait for its children, stop RViz/remaining ROS consumers, then stop the simulator. Ctrl+C on an action client alone is not proof that its server goal stopped.

Do not reset the whole world while the controller is standing. Use the explicit object-only reset between idle trials. If a full simulator reset is needed, shut down normally and restart all ROS consumers and RViz for the new clock epoch; initialize, engage and plan again. Object restoration is not insertion: no contact insertion or automatic release is performed by the skill.
