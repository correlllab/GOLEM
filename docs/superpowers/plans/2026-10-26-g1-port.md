# G1 Port into GOLEM camera_ready: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** GOLEM's `camera_ready` runs the Unitree G1 beside the H1-2, from one repo, one image set and one simulator runner (`--h12` default, `--g1`), and the H1-2's default behaviour stays unchanged.

**Architecture:**
- The G1 ROS packages come over from G1_GOLEM `df64d43` as separate packages under `core_ws/src/g1/`, using the shared `custom_ros_messages`.
- The robot is chosen at run time. `GOLEM_ROBOT` or `--g1` selects a compose overlay and the G1 path in the one RoboCasa entry point, `h1_robocasa/h12_mujoco.py`. That file dispatches to an `h1_robocasa/g1/` package before its H1 imports.
- The two robots share the sensor-bridge host, the measurement bridge and the task helpers. Their sensor models, DDS interface and main loop stay per robot.

- ROS 2 Humble (ament_python) and CycloneDDS 0.10
- `unitree_sdk2py` `c158c8d`

- onnxruntime 1.23.2
- Docker Compose and pytest/unittest
- MkDocs Material 9.7.7

## Decisions this plan implements

| Item | Decision |
|---|---|
| Interfaces | One `custom_ros_messages`; add `SetHandPose.srv` and `SkillRetrieveMemory.action`; no `g1_msgs` |
| Safety, controller, lower body, bringup, navigation | Separate G1 packages: `g1_safety_layer`, `g1_control`, `g1_locomotion`, `g1_bringup`, `g1_navigation`, plus `g1_description` and `g1_dex3` |
| Frontier explorer | G1's own node inside `g1_navigation`; a shared explorer is a later follow-up |
| Simulator | One runner for both robots: `h12_mujoco.py` with `--h12` (default) and `--g1` |
| Spatial memory | A shared robot-agnostic package plus the benchmark (Phase 5; it gets its own detailed plan) |
| Docs | G1 docs in GOLEM plus a MkDocs site; the demo videos stay out |
| History | Copy the code; each commit body cites `G1_GOLEM df64d43 <path>` |
| H1 safety-layer pin | Task 0: the latest `main` merged with the five `camera_ready` safety commits; merge `a178f0b` is already verified |

The sim design leaves some questions open. The plan takes its recommended defaults; change them before execution if you disagree:
- `h12_mujoco.py` keeps its name.
- Two loops sit behind one entry point.
- The G1 keeps calling `tick()` under its lock.
- The G1 uses `GOLEM_CAMERA_SCALE`, with a default of 1.0 for g1.
- There is one container name per service.
- `G1_DDS_INTERFACE` keeps its name.
- The new lock files follow the naming convention, so the next build is a full rebuild.
- The G1 is x86-only, and `configure_robot` rejects it on mac.
- There are no warnings for ignored knobs.
- The G1 sim unit tests stay out of CPU CI.

## Review Focus

1. **Stray `GOLEM_ROBOT=g1`:** a `GOLEM_ROBOT=g1` left in `docker/.env` must not switch the H1 test
   wrappers (`tests/stack/run.sh`, `tests/robocasa/run_in_container.sh`). An H1 run must not end up
   with a G1 sim. Test in Task 3.
2. **Missing `leprechaun_g1`:** on a checkout where `third_party/leprechaun_g1` isn't initialized,
   the H1 flows still build and run, because `launch_ros.sh` skips `g1_*` unless the robot is g1.
   G1 flows fail in `prepare_mounts` with the `git submodule update --init` command, before any
   container starts. Test in Task 3.
3. **G1 on domain 0 without a usable interface:** `ROS_DOMAIN_ID=0` with `GOLEM_ROBOT=g1` and an
   empty, missing, DOWN or IPv4-less `G1_DDS_INTERFACE` is refused before the confirmation prompt.
   Test in Task 3.
4. **Unsupported FrameTask fields:** a FrameTask goal with `relative: true` or `slow_mode: true`
   (or a NamedConfig goal with `slow_mode: true`) sent to the G1 controller aborts with a log line
   naming the field. It must never run an offset as an absolute target. Test in Task 7.
5. **Mismatched stack and sim:** a G1 bringup started against the H1 sim, or the reverse, on the
   same domain is refused by `wait_for_sim.py` (`mode_machine` 5 for g1, 0 for h12) before any
   command is sent. Test in Task 17.
