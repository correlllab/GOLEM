# Faster RoboCasa sims Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Raise both RoboCasa sims' real-time factor (target 0.95x in the full stack) without turning off a sensor or lowering its resolution, and give both robots the real MID-360 scan pattern at 20,000 points per frame.

**Architecture:** Four tiers, each landing with its closed-loop tests green before the next starts. Tier 1 moves work off the physics thread and onto the fast cores with no change to physics or the topic surface. Tier 2 replaces both robots' lidar models with one shared MID-360 module (`golem_robocasa/mid360.py`) that casts the real pattern on the GPU (EGL depth renders) or, without one, exactly on the CPU. Tier 3a excludes fixture-internal collisions at scene build. Tier 3b moves the `robocasa` image to MuJoCo 4.0 (or 3.17), behind a spike and the user's check of the walking.

**Tech Stack:** Python 3.10, MuJoCo 3.3.1 (`robocasa` image; Tier 3b changes it), robosuite/RoboCasa, cyclonedds-python 0.10.2 via `unitree_sdk2py`, rclpy (Humble), numpy, EGL, Docker Compose, bash.

**Spec:** `docs/superpowers/specs/2026-11-05-sim-speed-design.md`

## Global Constraints

- Topics, frames, message types and rates stay what the real robots publish; only the lidar's points change (Tier 2), and `tests/robocasa/surface/{h12,g1}.json` are re-recorded only in Tier 2.
- No physics change in Tiers 1 and 2. Physics stays on CPU MuJoCo (no MJX, no MuJoCo Warp, no Isaac).
- Ground truth is never on by default (CLAUDE.md §8). No new ungated ground-truth publisher.
- The Mac may get slower, never broken: every Tier 1-3a change must leave the Mac launch working (CPU lidar path, no pinning).
- The H1-2 sim's default behaviour is preserved, and nothing on the G1 path changes the H1-2's (CLAUDE.md §8).
- The `ros` image keeps MuJoCo 3.2.3 (MJPC's ABI). The Mac image keeps 3.3.1. Unitree's G1 models stay byte-for-byte upstream.
- New pip dependencies go at the END of a Dockerfile through a lock step (`-c /opt/golem-locks/<step>.txt`; `tests/docker/test_source_pins.py`).
- Never bump `livox_ros_driver2` off `13eb05e`.
- Tests run in disposable containers on a non-zero `ROS_DOMAIN_ID` (never 0), never in the user's `golem_ros` container. Never touch `core_ws/src/golem_bringup/rviz/g1/g1.rviz` or the `livox_ros_driver2` submodule change.
- Comment rules: CLAUDE.md §8 "Comments and docstrings" (purpose line per definition, `SAFETY:` prefix, no change narration). CLAUDE.md and AGENTS.md (kept identical) are updated for every knob or behaviour a task changes.
- The MID-360 pattern: MuJoCo-LiDAR's `mid360.npy` (MIT, `Copyright (c) 2025 Yufei Jia`), 800,000 (azimuth, elevation) pairs in radians, azimuth 0-2pi, elevation -0.126 to 0.910 rad, in firing order; fired at 200,000 points per second of sim time; 10 Hz frames of 20,000 points; `line` = point index mod 4; blind zone 0.1 m; max range 40 m; range noise 0.02 m (1 sigma, my call within the spec's 2-3 cm).
- MuJoCo 4.0.0 is tried first in Tier 3b; 3.17.0 is the fallback.

## Review Focus

1. A MuJoCo auto-reset puts sim time back to 0: the lidar scanner must start a new frame, not wait for the old time or publish a frame spanning the reset (Task 6 test `test_scanner_restarts_after_time_goes_back`).
2. A tilted or fallen robot: the GPU caster must cover every ray at any sensor orientation, not only upright (Task 7 test `test_gpu_matches_cpu_at_any_orientation`).
3. EGL missing or failing at runtime: `auto` falls back to the CPU caster with one log line, never a crash (Task 7 test `test_auto_backend_falls_back_to_cpu`).
4. A host that is not hybrid (the Mac, an AMD desktop, a VM), or an explicit cpuset naming cores that do not exist: no pinning, or a clear refusal before any container starts (Task 3 tests).
5. The viewer closed by the user while the physics runs: both sims stop as they do today, and the viewer thread never touches `MjData` outside its lock (Task 1 test `test_viewer_sync_stops_when_handle_closes`).
