# Change report: golem_bringup, golem_robocasa and the G1's debug-mode start-up

The changes a user of either robot must know, one row per change, with the task that makes it.

| Task | Robot | Before | After | Why / what to do |
|---|---|---|---|---|
| 1 | H1-2, G1 | The RoboCasa sim lived in `h1_robocasa/` and was bind-mounted at `/home/code/h1_robocasa`. | It lives in `golem_robocasa/` and is mounted at `/home/code/golem_robocasa`. `h12_mujoco.py` and every module inside keep their names, and the sim does the same as before. | The directory is the sim of both robots, not the H1-2's. Restart the `golem_sim_robocasa` container after pulling: a running one keeps the old mount, and a stack that sets `PYTHONPATH=h1_robocasa` must name `golem_robocasa`. An image built before the rename still runs, with its `WORKDIR` unchanged, since the launchers `cd` to the new path; a rebuild is not needed. |
| 2 | H1-2, G1 | Four packages marked "unused, awaiting deletion" still built and installed: the submodules `h12_safety_layer` and `h12_ros2_controller`, and `g1_safety_layer` and `g1_control` in `core_ws/src/g1/`. Their nodes wrote the same topics as `golem_safety` and `golem_upper_ik`. | All four are deleted (the two submodules' gitlinks and `.gitmodules` entries too; their GitHub repos are untouched). So are the four tools that imported them (`golem_safety/tools/crc_fixtures.py` and `snapshot_old_limits.py`, `golem_upper_ik/tools/snapshot_old_controller.py` and `snapshot_old_fk.py`). The fixtures they wrote stay as recorded data, and `test/fixtures/README.md` in each package says which package and commit each was recorded from. The H1-2's joint table is `golem_safety/tools/h12_joint_limits.py`, which `tools/generate_robot_data.py` writes `robots/h12.yaml` from; `h12.yaml`'s header line names it. | Nothing launched them, so nothing about a run changes. After pulling, `git` leaves the working trees of the removed submodules behind, and colcon would still build them from there: delete `core_ws/src/h12_safety_layer` and `core_ws/src/h12_ros2_controller`, and any leftover `core_ws/src/g1/g1_safety_layer` and `core_ws/src/g1/g1_control`. Deleting the packages' generated build output is the next row. |
| 2 | H1-2, G1 | A workspace built before this change keeps `core_ws/build/<pkg>` and `core_ws/install/<pkg>` for each of the four packages, so `ros2 pkg prefix h12_safety_layer` (and the other three) still answers and their executables stay on the path. `container_cache/g1_tests/{build,install}/<pkg>` holds the same for the G1 tests. | The four packages are gone from the workspace once those directories are deleted; `ros2 pkg prefix <name>` then fails for each. | Run once, from the repo root, on every host that built the workspace: `rm -rf core_ws/build/{h12_safety_layer,h12_ros2_controller,g1_safety_layer,g1_control} core_ws/install/{h12_safety_layer,h12_ros2_controller,g1_safety_layer,g1_control} container_cache/g1_tests/{build,install}/{h12_safety_layer,h12_ros2_controller,g1_safety_layer,g1_control}`. A file left root-owned by a container needs `sudo`. The next `colcon build` rebuilds only what changed. |
| 2 | G1 (the H1-2's configs log nothing) | Every safety config's `logging.base_dir` was `/tmp/g1_safety_layer` (G1) or `/tmp/h12_safety_layer` (H1-2); the G1's `.npz` chunk logs went to `/tmp/g1_safety_layer/<run>/` in the container. | Every config's `logging.base_dir` is `/tmp/golem_safety`: the G1's logs go to `/tmp/golem_safety/<YYYYmmdd-HHMMSS>-<pid>/`. `docs/g1/first-session.md` and `docs/g1/safety.md` say so. | Copy the logs out of `golem_ros` from the new path (`docker cp golem_ros:/tmp/golem_safety ...`) and pass it to `combine_chunks.py --load`. Logs from earlier runs stay where they were written. |
